# Style guide for pt-BR translations (human or machine-assisted)

Use this together with the general rules in [docs/README.md](../README.md#translations)
and the [glossary](../glossary.md). A machine-assisted draft is stamped `status=machine`
and becomes `current` only after a native speaker reviews it.

You are translating AI Prism documentation from English into Brazilian Portuguese.

- Audience: the person who deploys and operates AI Prism in their company's own
  Databricks workspace, a contributor, or a security reviewer. Never write "para um
  cliente": the reader is the company that runs the app.
- Address the reader as "você"; prefer impersonal or imperative phrasing ("rode",
  "abra", "confira"). Use Brazilian forms only: "arquivo", "tela", "usuário",
  "registro" (never "ficheiro", "ecrã", "utilizador", "registo").
- Short sentences, active voice, no marketing tone. Keep the English paragraph order;
  do not add or drop sections, tables or code blocks.
- Screen labels: quote the pt-BR label from the glossary or from
  `client/src/lib/locales/pt/*.ts`, in italics, exactly as the UI shows it
  (*Configurações → Design system*).
- Never translate: product and platform names (AI Prism, Databricks, Lakebase,
  AI Gateway, Unity Catalog, Genie One, Genie Agents, Vector Search, MCP, Skills,
  Design system, workspace, bundle, service principal), commands, file names, env
  vars, API paths, JSON/YAML keys and anything inside a code block except comments.
- Keep technical loanwords that Brazilian engineers use as is: deploy, rollback,
  pipeline, token, endpoint, log, dashboard, smoke test, pull request, commit.
- Keep links working: link to the pt-BR page when it exists (`docs/pt-BR/...`), else
  to the English page; fix `#anchors` to the target's own headings.
- Line 1 is the marker; line 2 the H1; then the language switcher
  `[English](...) · **Português (Brasil)** · [Español](...)`.
