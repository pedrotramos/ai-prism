### Added

- **MCP Apps: interfaces interativas das tools MCP dentro do chat.** Quando uma tool MCP que o modelo chamou declara um
  recurso de interface (`_meta.ui.resourceUri`), o chat mostra, sob a resposta, o botão "Abrir app" com os domínios que
  o app pode contatar. Abrir carrega a interface da própria tool em um quadro isolado (`sandbox="allow-scripts
  allow-forms"`, origem opaca) servido por `GET /api/mcp-apps/view/:toolCallId` com uma CSP própria no cabeçalho, feita
  só com os domínios que o servidor declarou: o app não alcança a página, os cookies nem a API deste aplicativo. As
  chamadas de tool que o app faz passam pelas mesmas regras de uma chamada do modelo (classe de credencial, política de
  tools da organização, serviço oculto, token de quem pediu) e pedem confirmação com os argumentos completos; "mensagem"
  do app só preenche o compositor, sem enviar. No máximo 4 apps por resposta, 3 abertos por página, recurso de até
  1 MiB; uma tool só para app nunca é oferecida ao modelo. Migração `0016_tool_call_ui_resource` (coluna
  `chat_tool_calls.ui_resource`). A funcionalidade vem **desligada**: o administrador a liga em Configurações → Tools
  e o operador pode forçá-la desligada com `MCP_APPS_DISABLED=1`. Nova dependência de cliente
  `@modelcontextprotocol/ext-apps` fixada em `1.7.5` (ADR 0019). A verificação no gateway real ainda não foi feita.
  Uma política de CSP com mais de 4096 caracteres é recusada na captura (o resultado simples da tool permanece, código
  `csp_too_long`), nunca encurtada; e os erros das chamadas de tool de um app são registrados só como código.
